# AlexNet M8xN128 유틸리제이션 최적화 계획 — 2026-09-14

## 0. 이 문서의 위치

`DYNAMIC_ARRAY_BANDWIDTH.md`가 배열 크기와 대역폭 계약을 고정했고, 그 릴리즈
게이트 중 하나가 아직 `PARTIAL`이다:

> **PARTIAL:** Conv2-shaped issue duty is above 90%, but full Conv1 issue duty
> is 60.370%. Scanner/prefetch overlap is still required before calling the
> Conv1 supply path utilization-complete.

이 문서는 그 `PARTIAL` 항목을 포함해, **DSP를 추가하지 않고 회수 가능한 손실**을
전수 조사하고 조치 계획을 세운다. 배열 확장(M32, DSP 증설)은 이 문서의 범위가
아니다. 5절에서 그 이유를 정량으로 보인다.

측정 출처는 전부 리포지토리 내 기존 산출물이다. 해석으로 유도한 값은 **[유도]**로
표시한다.

## 2. 손실 분해

전체 손실은 **서로 독립인 네 가지**로 완전히 분해된다.

```
PE util = issue duty  x  lane 충전율

  issue duty  = issue_cycles / total_cycles      ← 발행 자체를 못 하는 시간
  lane 충전율 = useful_slots / (issue x M_lanes)  ← 발행은 하나 레인이 빔
```

| # | 손실 | 크기 | 원인 |
|---|---|---:|---|
| L1 | 스캔 버블 | Conv1 39.3% | SCAN과 EMIT이 배타적 FSM 상태 |
| L2 | **M-tail** | **16~19%** | 출력 행 경계에서 M 그룹이 잘림 |
| L3 | post-reduce 드레인 | 7.0% | 타일 종료 후 파이프라인 배출 |
| L4 | intertile 전환 | 1.9% | 타일 간 전환 오버헤드 |

`issue_block=0`, `ce_stall=0`, `egress_block=0` 이므로 **postprocess/결과 배출
경로는 병목이 아니다.** 이 카테고리는 조사에서 제외한다.

### 2.1 L2가 M-tail임을 확정하는 증거

`PE util ÷ issue duty`(= lane 충전율)가 **출력 폭의 M16 정렬 나머지와 네 형상
모두에서 소수점 5자리까지 일치**한다.

| tag | 출력 폭 W | 측정 util/duty | `W / (ceil(W/16)*16)` | 일치 |
|---|---:|---:|---:|:---:|
| 101 | 3 | 0.18750 | 3/16 = 0.18750 | O |
| 104 | 55 | 0.85939 | 55/64 = 0.859375 | O |
| 102 | 27 | 0.84376 | 27/32 = 0.84375 | O |
| 103 | 13 | 0.81250 | 13/16 = 0.81250 | O |

### 2.1.1 대조 실험으로 인과 확정 (2026-09-14 실측)

상관만으로는 원인을 확정할 수 없으므로, **출력 폭이 M16 배수인 형상**을 프로파일
TB에 추가해 직접 검증했다 (`tb_alexnet_n8_rs_m4_feeder.sv`, tag 105~107).
가설이 맞다면 M-tail이 0이 되어 `pe_util == issue_duty`가 성립해야 한다.

| tag | 형상 | 출력 폭 | 예측 lane fill | 측정 `util/duty` | 판정 |
|---|---|---:|---:|---:|:---:|
| 105 | 16x16 K3 S1 P1 | 16 | 1.00000 | 76.393/76.393 = **1.00000** | 일치 |
| 106 | 17x17 K3 S1 P1 | 17 | 17/32 = 0.53125 | 45.203/85.089 = **0.53124** | 일치 |
| 107 | 32x32 K3 S1 P1 | 32 | 1.00000 | 78.208/78.208 = **1.00000** | 일치 |

**출력 폭이 M16의 배수면 lane 충전율이 정확히 100%가 된다.** 폭을 1만 늘리면
(16 → 17) 그룹 수가 1 → 2로 늘며 충전율이 53.1%로 급락한다. M-tail이 원인임이
인과적으로 확정됐다.

DPI 골든 모델 자체 검사도 통과했으므로(`FEEDER_PROFILE_PASS frames=7`) 위
수치는 **기능적으로 올바른 실행에서 나온 값**이다.

이로써 손실 모형이 전부 검증됐다:

```
PE util    = issue_duty x lane_fill      (두 손실은 독립·곱셈적)
lane_fill  = W / (ceil(W/M) * M)
scan_cycles = padded_h * padded_w        (2.2절)
```

원인은 피더가 **행 지역(row-local) M 그룹**만 발행하기 때문이다:

> `alexnet_n8_rs_m4_feeder.sv:7` — emits **row-local** M4 spatial groups

출력 행 하나를 `ceil(W/M)`개 그룹으로 자르고 마지막 그룹이 부분 그룹이 된다.
행 경계를 넘지 못하는 이유는 링 버퍼가 정확히 `MAX_KERNEL`행만 보유하기
때문이다 (3.2절).

**AlexNet 실제 레이어의 M16 lane 충전율:**

| Layer | 출력 폭 | 그룹 수 | 충전율 | 손실 |
|---|---:|---:|---:|---:|
| Conv1 | 55 | 4 | 85.9% | 14.1% |
| Conv2 | 27 | 2 | 84.4% | 15.6% |
| Conv3/4/5 | 13 | 1 | **81.3%** | **18.7%** |

## 3. 조치 항목

### A1. 링 버퍼 1행 확장 + 행 소유권 크레딧

**전제 조치.** A2와 A3가 모두 이것을 요구한다.

현재 링 용량 (`alexnet_n8_rs_m4_feeder.sv:67-70`):

```
RING_LOGICAL_DEPTH = MAX_KERNEL * MAX_PADDED_WIDTH = 11 * 228 = 2,508
RING_BANK_WORDS    = 512
RING_BANKS         = ceil(2508/512) = 5
READ_COPIES        = M_GROUP = 16        (PHYS_ROWS >= 4)
→ BRAM = 16 copies x 5 banks = 80 RAMB36   (리포트 실측 80과 일치)
```

링이 커널 높이와 **정확히 같아** 여유 행이 0이다. 그래서 (a) 스캔을 계속하면
활성 윈도우를 덮어쓰고, (b) 행 경계를 넘는 M 그룹을 만들 수 없다.

**조치**

1. `RING_LOGICAL_DEPTH`를 `(MAX_KERNEL + 1) * MAX_PADDED_WIDTH`로 확장
2. 행 단위 소유권 카운터 추가 — 쓰기 포인터가 현재 윈도우 점유 행을 침범 금지
3. 출력 행 완료 시 `stride`만큼의 입력 행 해제

**비용**

```
12 * 228 = 2,736 → ceil(2736/512) = 6 banks
BRAM = 16 x 6 = 96 RAMB36   (+16, 80 → 96)
```

디바이스 144 RAMB36 중 `DYNAMIC_ARRAY_BANDWIDTH.md` 자체 projection이 약 95를
예상하므로, 여기에 +16이면 약 111. 여유는 남지만 좁다. **A1 착수 전 전체 BRAM
예산을 재집계해야 한다** (6절 O2).

**리스크:** 중간. 소유권 로직 오류는 조용한 데이터 손상으로 나타난다. 기존
`window_ref` 스코어보드가 이를 잡도록 회귀를 먼저 확장한다.

### A2. M 그룹의 행 경계 확장 (L2 제거)

**단독 이득이 가장 크다.**

**조치**

출력을 행 단위가 아니라 `P = Hout * Wout`의 1차원 연속열로 취급해, M 그룹이
행 경계를 넘어 채워지도록 발행 인덱서를 변경한다. stride-1 레이어에서 출력 행
`g`는 입력 행 `g..g+K-1`, 행 `g+1`은 `g+1..g+K`를 쓰므로 **행 하나 분량의 여유
(A1)가 있으면 두 윈도우를 동시에 유지할 수 있다.**

**예상 이득** [유도] — lane 충전율이 100%로 수렴:

| Layer | 현재 | A2 후 | 배수 |
|---|---:|---:|---:|
| Conv1 | 85.9% | ~100% | 1.164x |
| Conv2 | 84.4% | ~100% | 1.185x |
| Conv3/4/5 | 81.3% | ~100% | **1.231x** |

전체 conv 사이클 [유도]: **969,089 → 802,541 (1.21x)**

**리스크:** 중간. M lane별 입력 행 인덱스가 그룹 내에서 달라지므로 주소 생성이
복잡해진다. `read_bank_select_q`가 이미 lane별로 분리돼 있어 구조적 장애물은
없다.

### A3. SCAN / EMIT 오버랩 (L1 제거)

`DYNAMIC_ARRAY_BANDWIDTH.md`의 `PARTIAL` 게이트가 요구하는 항목.

**현재 구조**

```
ST_IDLE → ST_SCAN → ST_READ_ISSUE → ST_READ_CAPTURE → ST_EMIT ─┐
            ▲                                                   │
            └───────────────────────────────────────────────────┘
```

`alexnet_n8_rs_m4_feeder.sv:399` — 스캔 중 그룹 끝점에서 `ST_READ_ISSUE`로
이탈한다. **발행하는 동안 입력 스캔이 완전 정지한다.**

스캔 비용은 **패딩 후 래스터 크기와 정확히 같다** (7개 형상 전수 일치):

| 형상 | 패딩 후 | `padded_h * padded_w` | 측정 scan_cycles |
|---|---|---:|---:|
| 16x16 K11 P2 | 20x20 | 400 | 400 |
| 27x27 K5 P2 | 31x31 | 961 | 961 |
| 13x13 K3 P1 | 15x15 | 225 | 225 |
| 16x16 K3 P1 | 18x18 | 324 | 324 |
| 17x17 K3 P1 | 19x19 | 361 | 361 |
| 32x32 K3 P1 | 34x34 | 1,156 | 1,156 |
| **224x224 K11 P2** | **228x228** | **51,984** | **51,984** |

즉 스캔은 **패딩 래스터 픽셀당 정확히 1사이클**이며, 배열 폭과 무관하다.

Conv1은 stride 4라 50,176픽셀을 훑어 출력 3,025개만 만든다. **Conv1 전용 문제**다.

**핵심 관찰 — 메모리는 이미 동시 접근이 가능하다**

`alexnet_n8_rs_m4_feeder.sv:266-272`의 링 뱅크는 서로 다른 주소에 쓰기 1 / 읽기
1이므로 Vivado가 simple dual-port BRAM으로 추론한다. **직렬화는 FSM에만 있고
메모리 포트 제약이 아니다.** 따라서 A3는 추가 포트나 메모리 복제를 요구하지
않는다.

**주의:** 기존 `prefetch_issue` (`:210`)는 *링 읽기 지연을 EMIT 안에 숨기는*
용도이며 이미 동작한다 (`read_issue_cycles=220`으로 무시 가능). **SCAN-EMIT
오버랩과는 다른 것이다.**

**조치**

1. SCAN을 FSM에서 분리해 독립적으로 진행하는 쓰기 엔진으로 변경
2. A1의 소유권 크레딧으로 활성 윈도우 보호
3. 스캔 소스 stall과 발행 stall을 독립 처리

**예상 이득** [유도]

```
Conv1:  132,284 → 79,860 cycles  (1.66x)
PE util: 51.881% → 85.93%
```

A2와 함께 적용 시 Conv1은 **132,284 → 약 68,600 (1.93x)**.

**리스크:** 높음. FSM 재구조화 범위가 가장 크다. A1/A2 완료 후 착수한다.

### A4. post-reduce 드레인 오버랩 (L3, 선택)

실측 `post_reduce=1674 / compute=23845 = 7.0%`. 타일의 마지막 K 토큰 이후
DSP 파이프라인(지연 4)과 누산·holding을 배출하는 구간이다.

**조치:** 타일 N의 드레인과 타일 N+1의 발행을 겹친다. PE에 이미 accumulator와
holding 레지스터가 분리돼 있어(`alexnet_packed_pe.sv:96-97`) 구조적 기반은 있다.

**이득:** 최대 7.0%. **리스크:** 중간 — `reduce_last` / `acc_clear` 정렬
assertion을 깨기 쉽다.

**판단:** A1~A3 완료 후 재측정하고 결정한다. 선행 조치들이 끝나면 상대 비중이
커지므로 그때 다시 평가할 가치가 있다.

### A5. zero-skip — 기각 (근거 기록용)

late layer의 activation sparsity는 실재하지만 **비용 대비 이득이 맞지 않는다.**

`PRE_RTL_SIGNOFF.md:228` 실측:

| Conv | Input zero | Pair both-zero | M32 all-zero | Kernel-row | Full-window |
|---|---:|---:|---:|---:|---:|
| Conv1 | 0.61% | 0.03% | 0.00% | 0.00% | 0.00% |
| Conv2 | 28.76% | 21.96% | 2.66% | 0.00% | 0.00% |
| Conv3 | 52.66% | 43.23% | 6.81% | 0.00% | 0.00% |
| Conv4 | 84.59% | 78.61% | **21.47%** | 0.00% | 0.00% |
| Conv5 | 82.37% | 75.96% | **19.23%** | 0.00% | 0.00% |

**기각 근거**

1. weight exact-zero는 1.19~3.88%뿐 → weight 측 스킵 불가
2. Kernel-row / Full-window가 **전 레이어 0.00%** → 구조적 스킵 불가
3. 앞단(Conv1/2)은 사실상 0
4. 사이클 이득이 **전체 conv의 9.3%**에 불과 [유도]
   ```
   Conv3 170,867 x 6.81%  =  11,636
   Conv4 227,875 x 21.47% =  48,925
   Conv5 151,965 x 19.23% =  29,223
   합계 ≈ 89,784 / 969,089 = 9.3%
   ```
5. K 스킵은 URAM weight replay 주소 점프를 요구해 **weight 경로까지 침범**한다.
   ping-pong은 "사이클당 1,024비트 순차 replay" 전제로 설계됐다
6. PE의 `reduce_last` / `acc_clear` 정렬 assertion과 충돌 위험

A2가 동일 규모 이상(1.21x = 21%)의 이득을 **훨씬 낮은 복잡도로** 준다. A5는
A1~A4 완료 후에도 격차가 남을 때만 재검토한다. 현재 결정(counter만 유지)을
유지한다.

## 5. 배열 확장을 우선하지 않는 이유

스캔 비용은 배열 폭과 **무관한 고정 비용**이다. 같은 Conv1 형상에서:

| | M8 피더 | M16 피더 |
|---|---:|---:|
| issue_cycles | 139,755 | 79,860 |
| **scan_cycles** | **51,984** | **51,984** |
| 총 cycles | 192,509 | 132,284 |
| PE util | 71.300% | **51.881%** |

배열을 2배로 넓혔는데 총 사이클은 **1.455배만** 줄었고 PE util은 오히려
71.3% → 51.9%로 **떨어졌다.**

M32 확장 시 [유도]: `issue ~45,600 + scan 51,984 = 97,600`, 스캔이 **전체의
53.3%**. M16 대비 **1.36배**에 그친다.

**A1~A3를 먼저 하지 않으면 배열 확장 투자가 회수되지 않는다.**

| O6 | `alexnet_m8n128_resident_weight_sa` 미검증 | 통합 시뮬이 첫 fill 핸드셰이크에서 행 |

---

## 7. 실행 순서

```
1. O2 (BRAM 예산 재집계)            — A1 착수 가능 여부 판정
2. A1 (링 +1행 + 소유권)            — 회귀 확장 먼저, 기능 변화 없음을 확인
3. A2 (M 그룹 행 경계 확장)         — 프로파일 TB로 lane 충전율 실측
4. 중간 측정 / OOC 합성             — BRAM·타이밍(O4) 재확인
5. A3 (SCAN/EMIT 오버랩)            — scan_cycles 감소를 실측
6. 재측정 후 A4 판단
```

각 단계는 기존 프로파일 TB(`tb_alexnet_n8_rs_m4_feeder.sv`)가 그대로 검증
수단이 된다. `issue_duty_pct` / `pe_util_pct`가 직접 출력되므로 **개선을 추정이
아니라 측정으로 확인할 수 있다.** 단계마다 이 두 수치를 기록한다.

### 검증 게이트

| 단계 | 통과 조건 |
|---|---|
| A1 | 기존 회귀 전부 PASS, 프로파일 수치 불변, BRAM 96 이하 |
| A2 | `pe_util/issue_duty`가 네 형상 모두 0.97 이상 |
| A3 | Conv1 `scan_cycles` 대폭 감소, `issue_duty` 90% 이상 |
| 공통 | OOC impl 200MHz WNS 양수, DRC 에러 0 |
