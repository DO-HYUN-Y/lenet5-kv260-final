# KV260 M4xN8 board-top build

This stage packages the AlexNet accelerator RTL as Vivado IP and connects it
to a K26 Zynq UltraScale+ PS, DDR, two AXI DMA instances, clock/reset, and
interrupts. The only implementation target is 200 MHz.

## Hardware boundary

The generated `system_wrapper` contains:

- one ZynqMP PS using the KV260 board preset;
- one 199.998002 MHz fabric clock/reset domain generated by an MMCM from the
  stock PS PL0 99.999001 MHz clock;
- the complete logical M4xN8 AlexNet graph accelerator;
- one 128-bit, MM2S/S2MM main DMA with DRE on both channels;
- one PS-owned 64-bit, MM2S-only camera DMA;
- one camera RGBX-to-N8 stream adapter;
- one 50,176-word URAM frame cache that replays Conv1 input eight times;
- one 128-bit non-coherent HP0 DDR path shared by the DMA ports;
- one control interconnect and one five-source PL-to-PS interrupt vector.

The USB camera itself is a PS/Linux device. Linux must capture a frame,
perform the frozen resize/crop/normalize/INT8 preprocessing, write the packed
frame to DDR, and start the camera DMA once. The PL caches the complete Conv1
input in 13 URAM288 blocks and replays it for all eight N8 output tiles while
the main DMA services weights, parameters, intermediate activations, and FC8
output.

## PS address and interrupt map

| PS physical base | Owner |
| ---: | --- |
| `0xA0000000` | AlexNet AXI-Lite control registers |
| `0xA0010000` | Main model/activation AXI DMA registers |
| `0xA0020000` | Camera MM2S AXI DMA registers |

The accelerator's own AXI-Lite master can access only the main DMA register
bank at `0xA0010000`. All three DMA memory ports map DDR low
`0x00000000..0x7FFFFFFF`.

`pl_ps_irq0` uses bit 0 for the accelerator, bit 1 for main MM2S, bit 2 for
main S2MM, bit 3 for camera MM2S, and bit 4 for a sticky malformed-camera-frame
error.

## Camera DDR buffer ABI

One preprocessed `224x224` RGB pixel occupies one eight-byte DDR word:

| Byte | Meaning |
| ---: | --- |
| 0 | signed INT8 model channel 0 |
| 1 | signed INT8 model channel 1 |
| 2 | signed INT8 model channel 2 |
| 3..7 | zero padding |

The buffer is exactly `224 * 224 * 8 = 401408` bytes and must be eight-byte
aligned. The camera DMA emits `TKEEP=0xFF`; the adapter forwards bytes 0..2 as
one 64-bit N8 word with `TKEEP=0x07`, zeros the other lanes, and checks both
the keep mask and exact final-pixel `TLAST` position. The frame cache then
replays those 50,176 words eight times at one word per cycle. Relative to the
previous eight-DMA runtime, this removes seven launches/waits and 2,809,856
camera DDR bytes per inference.

## Model DDR images

Recreate and verify the trained INT8 images from the official torchvision
checkpoint and the frozen calibration contract:

```sh
python -m alexnet.export_board_weights
python -m alexnet.verify_board_weights
```

The git-ignored output under `alexnet_output/int8_mlcommons500_board/` contains:

| File | Bytes | SHA-256 |
| --- | ---: | --- |
| `weights_board.bin` | 61,090,496 | `07e8583d9c18563672ffeb211746dfc432ba5b96d27039d01563d3fb8679ec3d` |
| `parameters_board.bin` | 165,504 | `0038da71fe9e4fc4454930b8a7f02e36d822e3cd6736388092c1429635c5a2ad` |

`board_manifest.json` fixes the eight layer offsets. The two blob base
addresses allocated by Linux must each be 128-byte aligned. Layer-relative
offsets and transfer lengths are eight-byte aligned and are legal because the
main DMA has DRE enabled.

The host-tested Linux driver and saved-image/live-camera polling runtime are in
`../../software/`. They allocate one page-aligned 61,767,680-byte region below
4 GiB, verify the hardware ID, check the PS PL0 input clock and the fixed
199.998002 MHz fabric-clock contract, load these two images, control the camera
DMA, and decode the 1,000 FC8 outputs. The timing-clean bitstream, overlay, and
target-built kernel module are loaded on the KV260. Coherent DMA `mmap`, RTL ID,
M4xN8/200 build word, and both clock readings passed the physical-board inspect
gate. The preceding non-cache release also passed trained saved-image and live
USB-camera inference, including a dog classification printed in the terminal.

## Reproduce

Run the camera adapter protocol regression:

```sh
vivado -mode batch \
  -source alexnet/stages/01_kv260_m4n8/scripts/run_camera_rgbx_axis_adapter.tcl
```

Package both custom IPs, recreate/validate the block design, synthesize,
implement, check timing/routing/DRC, generate the bitstream, and export the
hardware platform:

```sh
vivado -mode batch \
  -source alexnet/stages/01_kv260_m4n8/scripts/build_kv260_system.tcl
```

The vectorless estimate is 3.020 W total on-chip power. It is an implementation
estimate, not a board power or thermal measurement. The unchanged M4xN8

three `REQP-1934`, five `REQP-1935`, and one `RTSTAT-10`; no DRC error or
critical warning remains.
